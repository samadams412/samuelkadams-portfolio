## Problem

This was an 18-assignment web technologies course where each assignment built on the last, deployed to the same AWS EC2 instance the whole way through rather than reconstructed afterward. The end state is a database-backed CMS with a full authentication system, but the point of the case study is the build-up, not just the final screenshot.

## Infrastructure

The instance runs under a dedicated IAM user rather than root, applying least privilege from initial setup. nginx serves the site with HTTPS through a self-signed TLS certificate, and MySQL with phpMyAdmin handles the database layer.

## After launch

The instance sat untouched for about a month after the course ended. Pulling screenshots for this case study surfaced a dead MySQL service, killed by the kernel's OOM killer during a memory spike and stuck in a failed state after exhausting systemd's restart limit. The fix was a swapfile and a capped InnoDB buffer pool size. The full write-up, including the `dmesg` and `journalctl` evidence, is on DailyBlog: [My EC2 Instance Had Been Dead for a Month and I Didn't Know](https://sams-blog-gamma.vercel.app/blog/5de37cf4-5fec-4c87-a84d-087c5240c955).
